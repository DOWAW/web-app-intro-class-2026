# 私のアプリ設計

## 1. 題材（一文で）

自分のゲームを「プレイ中」と「デイリー」に分けて記録して、進み具合を管理するアプリ。

クリアを目指すゲームと、ソシャゲみたいに毎日やるゲームだと、管理したいことが違うので分けました。

## 2. テーブル設計

テーブル名: games

カラム:

- id
- title（ゲーム名）
- hardware（ハード名）
- kind（枠。clear か daily）
- done（済みかどうか。0か1）

done の意味は kind によって変わります。
clear のときは「クリアした」、daily のときは「今日やった」になります。

## 3. 変換表

todos → games
done → done（名前はそのままだけど意味を変えた）
todo.db → games.db
/todos → /games

追加したカラム: hardware, kind

## 4. やったこと

Level 1
題材とアプリ名を変えました。色は濃紺とオレンジにしました。

Level 2
カラムを2つ増やしました（hardware と kind）。
DBもAPIもHTMLもJSも全部直すことになりました。

Level 3
4つ作りました。

- 枠での絞り込み
- 件数の表示
- 並び替え
- デイリーの一括リセット

絞り込みと件数表示はJSだけでできます。
並び替えはSQLの ORDER BY を切りかえています。
一括リセットは PUT /games/daily/reset という新しいエンドポイントを作りました。
さわる場所がバラバラになるように選びました。

## 5. セキュリティの点検（第8回の4つ）

- XSS ... 表示は createElement と textContent でやっています。innerHTML は使っていません
- SQLインジェクション ... SQLに入れる値は全部 ? を使っています
- バリデーション ... Pydantic の Field で文字数を制限しました。kind は値そのものも見て、違ったら400を返します
- エラーハンドリング ... 無いidは404を返します。JSは通信を全部 try-catch で囲んでいます

並び替えのところだけ注意がいりました。
? が使えるのは値だけで ORDER BY には使えないので、
使っていい並び順を先に用意しておいて、送られてきた文字はそこから選ぶためだけに使うようにしました。

確認したこと:

`<script>` や `<img onerror=...>` を入れてみましたが、そのまま文字として出ました。
`a'; DROP TABLE games; --` を入れてもテーブルは消えませんでした。
空文字と文字数オーバーは422、kind に変な値を入れると400、無いidは404が返ってきました。
